# WuWa Dashboard — context for Claude / Clio / Couch-Clio

Single-theme (Emberline) Wuthering Waves roster dashboard for A. Live-saved to Supabase; all writes go through the CLI mutator — the browser is read-only.

Full context: **read `README.md`**. This file is the carry-on.

## Stack at a glance

- **Next.js 16** (App Router, Turbopack, React 19) — read `node_modules/next/dist/docs/` before assuming API shapes from training data. `params` is a Promise; use `use(params)` in client components.
- **Tailwind v4** via `@import "tailwindcss"` in `globals.css`, which now carries only the base reset + body/color — **no `@theme` block, no `data-theme` tokens**. Emberline's palette lives as a JS const object (`E_PAL`) in `src/components/themes/emberline/styles.ts`, not as Tailwind classes.
- **Supabase** Postgres (`dashboard_profiles` table, JSONB column, profile key `andres-wuwa`). Anon key in client by design — but **read-only since the 2026-07-07 RLS lockdown** (anon is `SELECT`-only; public signups disabled). There is **no in-browser editing** — every write goes through the CLI, which uses the **service key** from the gitignored `.env` (`scripts/service-key.ts`). CHECK constraint on profile column was dropped — arbitrary keys are fine now.
- **Emberline is the sole theme** — deep abyssal teal with element-reactive ember accents and the "Resonance Instrument" type stack (Chakra Petch 500 display / Familjen Grotesk body / Martian Mono HUD). Everything lives in `src/components/themes/emberline/` (`primitives.tsx` = `ECard`/`EKpi`/`EShell`/…, `styles.ts` = the `E_PAL` palette). No theme switcher, no `data-theme`, no per-theme dispatchers — `src/components/top-bar.tsx` and the app pages render Emberline directly. Fully **responsive** (mobile pass 2026-07-20): a two-stage idiom via `src/lib/use-dashboard-viewport.ts` — `isTablet` ≤1024 collapses structure, `isMobile` ≤700 adjusts fonts/padding/heroes; wide tables scroll inside their cards; the FLEX card button is desktop/tablet-only.

## Common tasks

**Update a value:** Use the CLI — `npm run update -- help` for the full surface. Couch-Clio runs it on PowerShell (Win) or terminal (Mac); Claude Code runs via Bash.

**Sync convene (gacha pull) history:** `npm run convene`. Requires the convene URL to be cached in the WuWa logs first — **launch WuWa → open Convene History in-game**, then run it. Auto-finds the URL in `Client.log` or the webview `debug.log` — Kuro XOR-obfuscates `Client.log` since ~2.x (odd low-nibble bytes ^0xA5, else ^0xEF); the script tries raw text first, then decodes (`xorDecodeLog`). Queries all 9 pools from Kuro's official API — the 7 permanent + collab pools 10/11 (Edgerunners+). Collab pages log a **separate record_id** and creds are asymmetric (main record_id can't see collab pools), so the script gathers every credential set from the logs and falls back per pool; **open BOTH Convene History pages in-game** (regular + collab) when a collab is live. Archival-merges into the `andres-wuwa-pulls` Supabase row (separate from the roster blob). Kuro only serves a rolling ~6-month window; the merge keeps everything older we've already captured (boundary-splice on `time`, never deletes) so the archive outlives the game's retention. Flags: `--dry` (fetch + print, no write), `--url "…"` (paste URL manually), `--game "F:\…"` (override install dir; default `F:\Wuthering Waves\Wuthering Waves Game`).

**Import historical pull data:** `npm run convene:import -- --file "path.json"` grafts pre-window pulls from an old tracker export (records OLDER than the current archive only; in-window records ignored since the API is authoritative there). **Preview by default — writes nothing without `--commit`.** Tolerant parser (flat array or banner-keyed object, loose field names); if a file won't map, eyeball a sample and extend `normalize()` in `scripts/convene-import.ts`. Merge logic for both sync + import lives in `src/lib/convene-merge.ts` (`mergeWindow` / `graftOlder`).

**Add a resonator:** follow **`docs/adding-a-resonator.md`** — the proven end-to-end runbook (research → key refresh → pak ground-truth → CLI → asset rip → ship), written live during the Yangyang: Xuanling add. Core command: `npm run update -- addresonator <name> <element> <weaponType> <role> [seq=S0] [level=0]` (e.g. `addresonator Lucy Spectro Pistols "Main DPS" S0 90`). Validates the enum fields, creates the live Supabase entry + a blank ATK/CR/CD/ER audit stub, auto-stubs the echo build + signature weapon, **and syncs `public/data.json`** (CRLF-preserving) so `generateStaticParams()` emits the new `/r/<name>/` page — still needs a **rebuild + push** to go live on GH Pages. Then fill stats/echoes/weapon with the usual commands. Portraits auto-resolve by name: drop `<name-lower>.png` in `public/portraits/` and `<Name>_Full_Sprite.webp` in `public/tall-portraits/` (or add a `PORTRAIT_OVERRIDES`/`TALL_OVERRIDES` entry in `src/lib/portraits.ts` for off-convention filenames).

**Add / reorder a benchmark team:** `npm run update -- addbench "<A,B,C>" <best> [avg= worst= spread= deaths= element= notes= pos=]` creates a new Overdrive benchmark. `<best>` is the headline clear time (`M:SS`); `avg`/`worst` default to `best`, `spread` auto-derives from `worst-best`, `deaths` defaults to 0, and `element` auto-derives from the team's resonator elements (`"Spectro+Electro"`) — a member not yet in the roster is skipped with a warning (the cover portrait then falls back, see below). By default it **inserts at the best-time-sorted slot** (fastest on top) without disturbing the existing curated order; `pos=<N|end>` overrides. The whole board keeps the invariant **`rank === array position`** (auto-renumbered after every mutation), since the Emberline render keys off both. Reorder with `benchmove <rank> <up|down|top|bottom|N>` (manual) or `benchsort [best|average|worst]` (re-rank everything by clear time — **opt-in**, because a pure time-sort demotes the hand-curated #1 hero team behind a faster-*average* lineup). Remove with `rmbench <rank>`. Edit times as before with `bench <rank> <field> <value>` / `deaths <rank> <n>`. **No rebuild needed** — Teams reads live from Supabase. Any command takes `--dry` to preview the result without saving. Teams has **no inline edit UI** — it's a pure read surface; the CLI is the write path.

**Add an Endstate Matrix cycle:** `npm run update -- addcycle --file <cycle.json>` appends a whole new cycle (committed import files live in `scripts/cycles/`). The JSON is `{ id?, date, label, target, teamTarget, dayOne, teams[], lessons[] }`; each team is `{ order?, members[]|"A,B,C", buff, score, rating?, over5k?, notes }`. **`id` auto-assigns to max+1**, and **`totalPoints` / `teamsOver5k` / per-team `over5k` derive from scores** (≥5000) — if the file also states `totalPoints`/`teamsOver5k`, they're cross-checked and a mismatch warns (computed wins). `label` is the **flavor** name (e.g. "The Edgerunners Gambit"), matching C1/C2 — the in-game cycle name isn't stored. Ratings are `"" | B | A | S | SS | SSS | CROWNED | IRIDESCENT` (a `—`/`-` in the file maps to empty); `IRIDESCENT` renders the prismatic rainbow badge + bar, `CROWNED`/`SSS` get crown/amber styling, the rest render as plain badges. **No rebuild needed** — the Cycles page reads live from Supabase. To edit an existing cycle's teams, use `cycle <id> team <order> …` / `cycleTotal <id>` instead.

**Add a weapon image:** Drop `Weapon_{Name_With_Underscores}.webp` into `public/weapons/`. Apostrophes are literal `'`, not `%27` — rename wiki downloads if needed.

**Add a resonator splash art (Emberline FLEX card canvas):** Drop `{Name_With_Underscores}_Splash_Art.webp` into `public/splash/` — sourced from the wiki's "`<Name> Splash Art`" files (`wutheringwaves.fandom.com` MediaWiki API resolves them), **alpha-trimmed to the content bbox** before webp'ing (the card sizes by content height). `splashArt()` in `src/lib/portraits.ts` maps roster names (punctuation stripped, spaces→underscores — "Yangyang: Xuanling" → `Yangyang_Xuanling_Splash_Art.webp`). These arts are transparent medallion compositions — never cover-crop them. A missing file gracefully falls back to the tall sprite on the card, so a fresh roster add works art-less until its splash is ripped. All 23 current roster members have theirs.

**Add sonata-effect icons:** Drop `{Set_Name_With_Underscores}.webp` into `public/sonatas/` (e.g. `Crown_of_Valor.webp`, `Void_Thunder.webp`). Rendered on the Echo Audit ECHO SET row via the `parseEchoSets`/`sonataIcon` helpers in `src/lib/sonata.ts` (Emberline calls them directly — the old `<SonataIcons>` wrapper component was deleted in the strip-down): a single `"X 5/5"` shows one icon, a hybrid `"X 3 + Y 2"` shows both with piece-count badges. **Missing/unmapped icons hide themselves** (graceful text-only fallback via `onError`), so a partial set of files is fine — no broken-image boxes. The 22 sets in use: `Celestial_Light, Chromatic_Foam, Crown_of_Valor, Dream_of_the_Lost, Eternal_Radiance, Flaming_Clawprint, Frosty_Resolve, Gusts_of_Welkin, Halo_of_Starry_Radiance, Havoc_Eclipse, Lingering_Tunes, Midnight_Veil, Molten_Rift, Moonlit_Clouds, Pact_of_Neonlight_Leap, Rejuvenating_Glow, Rite_of_Gilded_Revelation, Shadow_of_Shattered_Dreams, Thread_of_Severed_Fate, Trailblazing_Star, Void_Thunder, Windward_Pilgrimage`. (The 3.4 Edgerunners additions — Lingering_Tunes, Rite_of_Gilded_Revelation, Shadow_of_Shattered_Dreams — were sourced from Game8's set pages and downscaled to 64×64 RGBA webp to match.)

**Fill a signature weapon (passive / why-cracked / stats):** CLI `npm run update -- sigweapon "<weapon name>" <field> "<value>"` (fields: passive, synergy, passivename, baseatk, mainstat, mainstatvalue, type, wearer). Addressed by **weapon name**, not resonator. New weapons get a blank stub automatically (`ensureSignatureWeapons`); `addsigweapon` creates one explicitly.

**Set an echo's species + per-slot sonata (drives the echo art):** `npm run update -- echoslot "<name>" <1-5> echo "<species>"` (e.g. `"Inferno Rider"` — validated against `src/lib/echo-icons.json`, unknown names warn but save; `-` clears) and `echoslot "<name>" <1-5> sonata "<set name>"` (canonical set name, no piece count; `-` clears). Species drives the monster-portrait art on the Emberline echo cards via `public/game/echoes/<id>.webp`; sonata puts the per-slot set icon on each. The 193-name → icon-id map was built from the pak SQLite dbs (`db_phantom.db`) joined with Dimbreath WutheringData's MultiText — regenerate after a patch with `wuwa-extract/build_echo_names.py`.

**Set forte levels:** `npm run update -- forte "<name>" <basic> <skill> <circuit> <liberation> <intro> [nodes=8]` (levels 1-10, nodes = unlocked side bonus nodes 0-8). Renders the Forte panel on the Emberline resonator page (and the FLEX card); absent forte hides the section. Read-only — the CLI is the write path. Per-character skill icons live in `public/game/forte/<name-lower>/` (Kuro naming: B1 = skill, C1 = liberation, Y = circuit). **The tree's Basic + Intro glyphs are NOT in the char's SkillIcon atlas** (intro's SP_*QTE sprite is literally blank in the pak) — they ship as `basic.webp`/`intro.webp` per char, extracted from an in-game forte-page screenshot (luminance→alpha + circular mask; see `wuwa-extract` scratch scripts). Fallback chain in `game-icons.ts`: per-char file → (basic only) shared per-weapon glyph in `public/game/skill-common/` → hide. Only Aemeath's set exists so far — rip more with `wuwa-extract` (`texdir` the char's `Atlas/SkillIcon/SkillIcon<Codename>/` for the atlas + `props` the TPI + `crop_lgui_sprites.py`, plus a forte-page screenshot for basic/intro).

**Ripped game assets (`public/game/`):** `echoes/` (228 monster heads, 256px), `stats/` (17 stat glyphs, semantic names), `elements/` (6 round badges keyed by ElementName), `forte/aemeath/`, `skill-common/` (5 weapon-type basic-attack glyphs). Path helpers + stat-label → glyph mapping in `src/lib/game-icons.ts`; everything degrades gracefully (onError hides, placeholders render) so partial asset coverage never breaks a page. Re-rip after a patch via `wuwa-extract/ship_to_public.py`.

**FLEX card (Emberline):** the `✦ FLEX CARD` button on the resonator page (**desktop/tablet only** — hidden on mobile) opens a fixed 1520×880 composed build card (splash-art canvas — portrait + stats + rating + weapon + forte + echo cards) with client-side PNG export via `html-to-image` (2× pixel ratio → 3040×1760). Chromium-only export — Firefox's `html-to-image` path fails. Component: `src/components/themes/emberline/flex-card.tsx`, reusing exported medals/icons from `emberline/resonator.tsx`.

**Enter / audit echoes (per-resonator):** Each resonator has an `EchoBuild` — 5 slots, each with a **per-echo cost** (default spread 4/3/3/1/1), a main stat + value, and up to 5 substats (stat + roll value). The Emberline ECHO AUDIT panel grades each echo (and the build) **for that resonator** via a per-resonator stat-weight profile, seeded from buildType + element. CLI: `npm run update -- echoslot "<name>" <1-5> main "<stat>" [value]`, `echoslot "<name>" <1-5> sub <1-5> "<stat>" <value>`, `echoslot "<name>" show`, `echoweight "<name>" "<stat>" <0..1>`, `echoweight "<name>" reset`. Blank builds are auto-stubbed (`ensureEchoBuilds`). Scoring math is pure in `src/lib/echo-audit.ts` (imported by both the UI and the CLI). It's a **stat grade only** — set bonuses (2pc/5pc) are NOT scored; `echoSet` still holds the set name separately.

**Non-standard cost spreads:** Cost is per-echo, so a resonator can run a layout other than 4-3-3-1-1 — e.g. HP scalers like Cartethyia run **4-4-1-1-1** (a second 4-cost main slot instead of the 3-cost). Set it via `npm run update -- echoslot "<name>" spread 4-4-1-1-1` (whole spread) or `echoslot "<name>" <1-5> cost <1|3|4>` (one slot). Changing a slot's cost auto-clears its main stat if that stat isn't valid for the new cost's pool. Total cost budget in-game is 12; the CLI warns if a spread exceeds it but doesn't block. The main-stat pool is keyed by each echo's own cost (`MAIN_STAT_POOLS[echo.cost]`), and scoring (`scoreEcho`/`scoreBuild`) reads `echo.cost`, so spreads are fully supported end-to-end.

**Check a resonator's overall rating:** The Emberline resonator page shows a `RESONATOR RATING` panel up top — one grade blending echo + stats + signature + sequence ("OPTIMIZER" weighting: build quality over investment). Read it from the terminal with `npm run update -- rating "<name>"`. Read-only; tune weights/curves in `src/lib/resonator-rating.ts`.

**Change how a value renders:** Find it in `src/components/themes/emberline/{page}.tsx` — Emberline owns every render.

## Don't / gotchas

- **Don't** reinstate the static `src/lib/data.ts` — it was removed deliberately when Supabase landed. Data must be read via `useData()` so live edits propagate.
- **Don't** try to reintroduce in-browser editing — `EditableField`, `edit-context`, `AuthGate`, and `src/lib/auth.ts` were all deleted in the strip-down. Every page is read-only in the browser; the CLI is the only write path.
- **Don't** refactor inline styles into Tailwind utility classes wholesale — the prototype at `../.design-handoff/design_handoff_wuwa_roster/` is the source of truth for visual fidelity. Surgical Tailwind use is fine; mass conversion is not.
- **Don't** add `width: 100%` to tall-portrait `<img>` — Tailwind v4 preflight already sets `max-width: 100%`, which fights the explicit `height: 105%` and squishes the portrait. The fix `width: auto; maxWidth: "none"` is already inline on every tall-portrait; preserve it.
- **Don't** treat the bundled `public/data.json` as the source of truth — it's the seed, only read once if the Supabase row is missing.
- **Couch-Clio runs commands natively.** Don't write instructions as "tell A. to run X" if she can just run X herself.
- **Spine atlas pages are WebP, not PNG** (2026-06-09: 116MB → 28MB). When carving a new bundle, convert each texture page with `cwebp -q 90 -alpha_q 100 -m 6 page.png -o page.webp`, point the `.atlas` page line at the `.webp`, and don't commit the PNG. spine-player loads pages as plain images, so the format is transparent to it.
- **`<SpinePortrait>` wants a `fallback`** — pass the static bust `<img>` so the cell shows it during the skel/atlas fetch and degrades to it if WebGL/loading fails (it's an underlay, auto-hidden once the live skeleton paints). Players also lazy-init via IntersectionObserver, and the `viewport` prop is compared by value (inline literals won't churn the player). The cover strip no longer wires this by hand — use `<CoverPortrait name filter>` which owns the Spine→tall→bust chain for all themes.
- **A new cover-strip resonator with no `TEAM_FRAME` entry uses `DEFAULT_FRAME`** (centered, height 245%). That's a safe neutral but may need a live-dial — measure the sprite's alpha bounds (head-top + head→chest band) like the other entries in `src/lib/portraits.ts` once you can see it framed in the Teams cell.
- **Benchmark `rank` must equal array position** (1-based). The CLI's `renumberBenchmarks()` enforces it after every add/move/sort/remove; don't hand-edit a `rank` out of sync — the Emberline render and the bar-width math assume the order.

## Active scope

- **Convene (pull history) section:** SHIPPED (`/convene` — global KPIs, banner selector, 5★ timeline, pity bar, 50/50 win/loss/guar tags, distribution histogram) in the Emberline theme. Reads `usePulls()` data and handles loading/error/empty status screens. 50/50 is derived from the fixed standard-5★ pool (Calcharo/Encore/Jianxin/Lingyang/Verina), no banner-date mapping. Read-only — synced via `npm run convene`.
- **Echo Audit section:** SHIPPED on the Emberline resonator page — overall stat-grade header + cost slots with main/substat, per-echo grade chips, quality dots/bars, dead-stat strikethrough, plus the ripped-asset enrichment (monster-portrait species art, per-slot sonata icons, stat glyphs) on the echo cards. Read-only render of the `scoreBuild`/`scoreEcho` output — the CLI (`echoslot`/`echoweight`) is the write path. Only lists slots that actually grade (blank stubs hidden). Per-resonator stat weights seeded from buildType+element, tunable via CLI. **Stat grade only** — set-bonus (2pc/5pc) evaluation is out of scope. Default weight seeds in `echo-audit.ts` (`DEFAULT_WEIGHTS`) are starting points, not gospel — tune as needed. **Cost is per-echo** — non-standard spreads (e.g. an HP scaler's 4-4-1-1-1) are supported via `echoslot spread`/`cost` CLI (see Common tasks).
  - **Grading recalibrated (2026-05-30):** `rollQuality` is now floor-aware (`value/max` — a min roll is ~its real fraction of ceiling, NOT zero; the old `(value-min)/(max-min)` pinned floor rolls to 0 and made correct-but-low builds grade like off-stat garbage). Substats normalize against a REALISTIC ideal (top-5 relevant stats at `Q_TARGET = 0.75` = "thrilled to get this" = S), and rolls above target overflow past 100 into the prestige zone. Ladder is now **D → C → B → A → S → SSS → ✦** (`gradeOf`): D is reserved for genuinely off-stat builds, S = optimal peak, SSS/✦ are the rare overflow tiers. The prestige tiers (**S / SSS / ✦**) render **gold with a glow** via `gradeColor` in `src/components/themes/emberline/resonator.tsx` (`E_PAL.gold`). Build headlines are diagnostic (`scoreBuild` branches on `avgMainMatch`), so "right stats, low rolls" no longer reads as "off-stat waste".
- **Resonator Rating section:** SHIPPED on the Emberline resonator page — `RESONATOR RATING` panel at the TOP of the profile, hero-sized grade medal + 4 sub-bars. Blends **Echo 35 / Stats 35 / Sig 15 / Seq 15** ("OPTIMIZER" soul — build quality over investment; an f2p god-build can outscore a sloppy whale) into one grade on the **same ladder** as the echo audit. Sub-scores: echo = `scoreBuild` (can overflow >100 → feeds rating prestige), stats = reuses each `AuditStat._status`, sig = on-sig (R1 80→R5 100, green) vs off-sig (52→70), seq = S0 60 floor→S6 100. Missing inputs renormalize (not punished). Read-only CLI `npm run update -- rating <name>`. Weights/curves in `resonator-rating.ts` are defaults — tune to taste.
- **Benchmarks (Teams page):** full CLI lifecycle — `addbench` / `bench` / `deaths` / `benchmove` / `benchsort` / `rmbench` (see Common tasks). No inline edit UI; Teams is a read surface (the CLI is the write path). Cover-strip portraits degrade **Spine → tall sprite → bust** via `<CoverPortrait>` (`src/components/cover-portrait.tsx`), so a benchmark can feature a brand-new resonator before its Spine bundle / tall art lands (e.g. the Edgerunners collab — Lucy, Rebecca — has busts + tall sprites but no Spine yet).
- In-browser editing: REMOVED across every page in the strip-down (Cycles included) — the CLI is the sole write path for all surfaces.
- EXPORT button (download JSONB snapshot): NOT ported from ZZZ. Supabase is the source of truth so it's lower priority; revisit if A. wants an offline backup gesture.
