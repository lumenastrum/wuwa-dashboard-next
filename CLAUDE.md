# WuWa Dashboard — context for Claude / Clio / Couch-Clio

Single-theme (Emberline) Wuthering Waves roster dashboard for A. Live-saved to Supabase; all writes go through the CLI mutator — the browser is read-only.

Full context: **read `README.md`**. This file is the carry-on.

## Stack at a glance

- **Supabase** Postgres (`dashboard_profiles` table, JSONB column, profile key `andres-wuwa`). Anon key in client by design — but **read-only since the 2026-07-07 RLS lockdown** (anon is `SELECT`-only; public signups disabled). There is **no in-browser editing** — every write goes through the CLI, which uses the **service key** from the gitignored `.env` (`scripts/service-key.ts`). CHECK constraint on profile column was dropped — arbitrary keys are fine now.

## Common tasks

**Update a value:** Use the CLI — `npm run update -- help` for the full surface. Couch-Clio runs it on PowerShell (Win) or terminal (Mac); Claude Code runs via Bash.

**Sync convene (gacha pull) history:** `npm run convene` — **open BOTH Convene History pages in-game** (regular + collab) first. Archival-merges into the `andres-wuwa-pulls` Supabase row (separate from the roster blob). Kuro only serves a rolling ~6-month window; the merge keeps everything older we've already captured (boundary-splice on `time`, never deletes) so the archive outlives the game's retention.

**Add a resonator:** follow **`docs/adding-a-resonator.md`** — the proven end-to-end runbook. A new resonator still needs a **rebuild + push** to go live on GH Pages. Portraits auto-resolve by name: drop `<name-lower>.png` in `public/portraits/` and `<Name>_Full_Sprite.webp` in `public/tall-portraits/` (or add a `PORTRAIT_OVERRIDES`/`TALL_OVERRIDES` entry in `src/lib/portraits.ts` for off-convention filenames).

**Add / reorder a benchmark team:** `npm run update -- addbench "<A,B,C>" <best> [avg= worst= spread= deaths= element= notes= pos=]` creates a new Overdrive benchmark. `<best>` is the headline clear time (`M:SS`); `avg`/`worst` default to `best`, `spread` auto-derives from `worst-best`, `deaths` defaults to 0, and `element` auto-derives from the team's resonator elements (`"Spectro+Electro"`) — a member not yet in the roster is skipped with a warning (the cover portrait then falls back, see below). By default it **inserts at the best-time-sorted slot** (fastest on top) without disturbing the existing curated order; `pos=<N|end>` overrides. The whole board keeps the invariant **`rank === array position`** (auto-renumbered after every mutation), since the Emberline render keys off both. Reorder with `benchmove <rank> <up|down|top|bottom|N>` (manual) or `benchsort [best|average|worst]` (re-rank everything by clear time — **opt-in**, because a pure time-sort demotes the hand-curated #1 hero team behind a faster-*average* lineup). Remove with `rmbench <rank>`. Edit times as before with `bench <rank> <field> <value>` / `deaths <rank> <n>`. **No rebuild needed** — Teams reads live from Supabase. Any command takes `--dry` to preview the result without saving. Teams has **no inline edit UI** — it's a pure read surface; the CLI is the write path.

**Add an Endstate Matrix cycle:** `npm run update -- addcycle --file <cycle.json>` appends a whole new cycle (committed import files live in `scripts/cycles/`). The JSON is `{ id?, date, label, target, teamTarget, dayOne, teams[], lessons[] }`; each team is `{ order?, members[]|"A,B,C", buff, score, rating?, over5k?, notes }`. **`id` auto-assigns to max+1**, and **`totalPoints` / `teamsOver5k` / per-team `over5k` derive from scores** (≥5000) — if the file also states `totalPoints`/`teamsOver5k`, they're cross-checked and a mismatch warns (computed wins). `label` is the **flavor** name (e.g. "The Edgerunners Gambit"), matching C1/C2 — the in-game cycle name isn't stored. Ratings are `"" | B | A | S | SS | SSS | CROWNED | IRIDESCENT` (a `—`/`-` in the file maps to empty); `IRIDESCENT` renders the prismatic rainbow badge + bar, `CROWNED`/`SSS` get crown/amber styling, the rest render as plain badges. **No rebuild needed** — the Cycles page reads live from Supabase. To edit an existing cycle's teams, use `cycle <id> team <order> …` / `cycleTotal <id>` instead. Letter grades (B–SSS) render as the ripped medal art (`gradeIcon`); CROWNED/IRIDESCENT keep pill styling. The plaque's record framing comes from the note text itself, never computed — don't trust raw cross-cycle score math (C1's 14,844 is an "ancients" era outlier).

**Add a Tower of Adversity season (crest ledger, `/toa`):** `npm run update -- addtoa --file <season.json>` (committed files live in `scripts/toa/`; `season-template.json` is the shape). JSON is `{ id?, date, label, window?, crestTarget?, floors[], lessons[] }`; each floor is `{ zone, tower, floor, boss?, members[]|"A,B,C", crests, time?, notes? }` with `zone` Stable|Experiment|Hazard|Overdrive, `tower` Resonant|Hazard|Echoing, `crests` 0-3, and `time` = time REMAINING on the floor clock (that's the crest currency in-game). `totalCrests` derives from floor crests (a stated value is cross-checked, computed wins). Edit later with `toa <id> floor <zone> <tower> <n> <crests|time|boss|notes|members> <value>` (a crest edit re-derives the season total); remove a season with `rmtoa <id>`. The kicker note convention applies to floor notes. **No rebuild needed** — the page reads live from Supabase. Zone/crest ceilings shown on the page live in `toa.tsx`'s `ZONE_MAX`, not in data.

**Add a Whimpering Wastes season (score ledger, `/wastes`):** `npm run update -- addwastes --file <season.json>` (committed files in `scripts/wastes/`; `season-template.json` is the shape). JSON is `{ id?, date, label, window?, chasmTarget?, torrentsTarget?, stages[], lessons[] }`; each stage is `{ stage 1-12, teamA, teamB, tokenA?, tokenB?, tokenAIcon?, tokenBIcon?, score, grade?, notes? }` — the in-game stage **name and Waters derive from the stage number** (1-6 Forbidden, 7-11 Chasm, 12 Torrents), grades are B|A|S (stage 12 alone extends to SS|SSS — the CLI warns on SS+ elsewhere), and per-Waters point totals derive from scores. `tokenAIcon`/`tokenBIcon` are rip ids into `public/game/wastes/tokens/<n>.webp` (01-52) — omit for a text-only token chip. Edit with `wastes <id> stage <n> <score|grade|notes|name|teama|teamb|tokena|tokenb|tokenaicon|tokenbicon> <value>`; remove with `rmwastes <id>`. Grade thresholds per stage tier render as bar ticks from `stageTiers()` in `wastes.tsx`. **No rebuild needed.**

**Add a resonator splash art (Emberline FLEX card canvas):** Drop `{Name_With_Underscores}_Splash_Art.webp` into `public/splash/` — sourced from the wiki's "`<Name> Splash Art`" files (`wutheringwaves.fandom.com` MediaWiki API resolves them), **alpha-trimmed to the content bbox** before webp'ing (the card sizes by content height). `splashArt()` in `src/lib/portraits.ts` maps roster names (punctuation stripped, spaces→underscores — "Yangyang: Xuanling" → `Yangyang_Xuanling_Splash_Art.webp`). These arts are transparent medallion compositions — never cover-crop them. A missing file gracefully falls back to the tall sprite on the card, so a fresh roster add works art-less until its splash is ripped. All 23 current roster members have theirs.

**Add sonata-effect icons:** Drop `{Set_Name_With_Underscores}.webp` into `public/sonatas/` (e.g. `Crown_of_Valor.webp`, `Void_Thunder.webp`). Rendered on the Echo Audit ECHO SET row via the `parseEchoSets`/`sonataIcon` helpers in `src/lib/sonata.ts` (Emberline calls them directly — the old `<SonataIcons>` wrapper component was deleted in the strip-down): a single `"X 5/5"` shows one icon, a hybrid `"X 3 + Y 2"` shows both with piece-count badges. **Missing/unmapped icons hide themselves** (graceful text-only fallback via `onError`), so a partial set of files is fine — no broken-image boxes. (The 3.4 Edgerunners additions — Lingering_Tunes, Rite_of_Gilded_Revelation, Shadow_of_Shattered_Dreams — were sourced from Game8's set pages and downscaled to 64×64 RGBA webp to match.)

**Fill a signature weapon (passive / why-cracked / stats):** CLI `npm run update -- sigweapon "<weapon name>" <field> "<value>"` (fields: passive, synergy, passivename, baseatk, mainstat, mainstatvalue, type, wearer). Addressed by **weapon name**, not resonator. New weapons get a blank stub automatically (`ensureSignatureWeapons`); `addsigweapon` creates one explicitly.

**Set an echo's species + per-slot sonata (drives the echo art):** `npm run update -- echoslot "<name>" <1-5> echo "<species>"` (e.g. `"Inferno Rider"` — validated against `src/lib/echo-icons.json`, unknown names warn but save; `-` clears) and `echoslot "<name>" <1-5> sonata "<set name>"` (canonical set name, no piece count; `-` clears). Species drives the monster-portrait art on the Emberline echo cards via `public/game/echoes/<id>.webp`; sonata puts the per-slot set icon on each. The 193-name → icon-id map was built from the pak SQLite dbs (`db_phantom.db`) joined with Dimbreath WutheringData's MultiText — regenerate after a patch with `wuwa-extract/build_echo_names.py`.

**Seed a FORTE-tab kit codex (the Clio kit breakdown):** `npm run update -- fortekit "<name>" --file scripts/kits/<name>.json` — whole-array replace from a committed JSON file (`[ { icon, name, type, take }, ... ]`; `show` lists, `clear` removes). The FORTE tab on the resonator page is LIVE and renders one card per ability: atlas icon + in-game name + slot label + a house-voice `take` (same register as WHY IT'S CRACKED — what the ability does for the player, not restated jargon). `icon` is the raw file stem under `public/game/forte/<name-lower>/` (Kuro naming: `basic`, `b1` skill, `y` circuit, `c1` liberation, `intro`, `t` outro, `d1`/`d2` inherents) via `forteKitIcon()`; a missing file degrades to a letter tile, so entries ship before their icon is ripped. Prose gotcha: `highlightStats` glues a trailing comma onto bare numbers (`stage 3,` renders "3 ,") — never end a numeric token with a comma in a take. Kit data is data-only (live via Supabase, no rebuild); source facts from the wiki's `<Name>/Combat` page via the MediaWiki API (`action=parse&prop=text` — direct fetches 402).

**Seed a CHAIN tab (sequence-node codex):** `npm run update -- chain "<name>" --file scripts/kits/<name>-chain.json` — exactly 6 nodes `[ { name, take }, ... ]`, S1 first (`show` lists, `clear` removes). The CHAIN tab (it took over WEAPON's inert strip slot — the weapon card lives on OVERVIEW) renders six S-numbered cards; **ownership derives from `Resonator.sequence` at render time** (owned = element-lit ◆ ACTIVE, unowned = dimmed ◇ NOT OWNED), so a `seq` bump lights the next card with no chain edit. Node facts come from the wiki Combat page's Chain Table (same MediaWiki API route as forte kits). The `highlightStats` no-trailing-comma rule applies to chain takes too.

**Set forte levels:** `npm run update -- forte "<name>" <basic> <skill> <circuit> <liberation> <intro> [nodes=10]` (levels 1-10, nodes = unlocked side nodes **0-10**). Single source of truth is `FORTE_NODE_MAX` in `src/lib/types.ts`; never re-hardcode the denominator. Renders the Forte panel on the Emberline resonator page (and the FLEX card); absent forte hides the section. Read-only — the CLI is the write path. Per-character skill icons live in `public/game/forte/<name-lower>/` — slots per `FORTE_SLOT_FILES` in `game-icons.ts`. **Basic/Intro glyphs may or may not be in the atlas**: Aemeath's `SP_*QTE` sprite is blank in the pak (hers came from an in-game forte-page screenshot, luminance→alpha + circular mask), but Camellya's is fine and all five shipped straight from the atlas — always alpha-count before assuming. Fallback chain in `game-icons.ts`: per-char file → (basic only) shared per-weapon glyph in `public/game/skill-common/` → hide. Aemeath + Camellya sets exist — rip more with `wuwa-extract` (`texdir` the char's `Atlas/SkillIcon/SkillIcon<Codename>/` + `props` the TPI + `crop_lgui_sprites.py`, which handles both TPI schemas).

**Ripped game assets (`public/game/`):** Path helpers + stat-label → glyph mapping in `src/lib/game-icons.ts`; everything degrades gracefully (onError hides, placeholders render) so partial asset coverage never breaks a page. Re-rip after a patch via `wuwa-extract/ship_to_public.py`.

**FLEX card (Emberline):** the `✦ FLEX CARD` button on the resonator page (**desktop/tablet only** — hidden on mobile) opens a fixed 1520×880 composed build card (splash-art canvas — portrait + stats + rating + weapon + forte + echo cards) with client-side PNG export via `html-to-image` (2× pixel ratio → 3040×1760). Chromium-only export — Firefox's `html-to-image` path fails. Component: `src/components/themes/emberline/flex-card.tsx`, reusing exported medals/icons from `emberline/resonator.tsx`.

**Enter / audit echoes (per-resonator):** Each resonator has an `EchoBuild` — 5 slots, each with a **per-echo cost** (default spread 4/3/3/1/1), a main stat + value, and up to 5 substats (stat + roll value). The Emberline ECHO AUDIT panel grades each echo (and the build) **for that resonator** via a per-resonator stat-weight profile, seeded from buildType + element. CLI: `npm run update -- echoslot "<name>" <1-5> main "<stat>" [value]`, `echoslot "<name>" <1-5> sub <1-5> "<stat>" <value>`, `echoslot "<name>" show`, `echoweight "<name>" "<stat>" <0..1>`, `echoweight "<name>" reset`. Blank builds are auto-stubbed (`ensureEchoBuilds`). Scoring math is pure in `src/lib/echo-audit.ts` (imported by both the UI and the CLI). It's a **stat grade only** — set bonuses (2pc/5pc) are NOT scored; `echoSet` still holds the set name separately.

**Non-standard cost spreads:** Cost is per-echo, so a resonator can run a layout other than 4-3-3-1-1 — e.g. HP scalers like Cartethyia run **4-4-1-1-1** (a second 4-cost main slot instead of the 3-cost). Set it via `npm run update -- echoslot "<name>" spread 4-4-1-1-1` (whole spread) or `echoslot "<name>" <1-5> cost <1|3|4>` (one slot). Changing a slot's cost auto-clears its main stat if that stat isn't valid for the new cost's pool. Total cost budget in-game is 12; the CLI warns if a spread exceeds it but doesn't block. The main-stat pool is keyed by each echo's own cost (`MAIN_STAT_POOLS[echo.cost]`), and scoring (`scoreEcho`/`scoreBuild`) reads `echo.cost`, so spreads are fully supported end-to-end.

## Don't / gotchas

- **Don't** reinstate the static `src/lib/data.ts` — it was removed deliberately when Supabase landed. Data must be read via `useData()` so live edits propagate.
- **Don't** try to reintroduce in-browser editing — `EditableField`, `edit-context`, `AuthGate`, and `src/lib/auth.ts` were all deleted in the strip-down. Every page is read-only in the browser; the CLI is the only write path.
- **Don't** refactor inline styles into Tailwind utility classes wholesale — the prototype at `../.design-handoff/design_handoff_wuwa_roster/` is the source of truth for visual fidelity. Surgical Tailwind use is fine; mass conversion is not.
- **Don't** add `width: 100%` to tall-portrait `<img>` — Tailwind v4 preflight already sets `max-width: 100%`, which fights the explicit `height: 105%` and squishes the portrait. The fix `width: auto; maxWidth: "none"` is already inline on every tall-portrait; preserve it.
- **Don't** treat the bundled `public/data.json` as the source of truth — it's the seed, only read once if the Supabase row is missing.
- **Couch-Clio runs commands natively.** Don't write instructions as "tell A. to run X" if she can just run X herself.
- **Spine atlas pages are WebP, not PNG** (2026-06-09: 116MB → 28MB). When carving a new bundle, convert each texture page with `cwebp -q 90 -alpha_q 100 -m 6 page.png -o page.webp`, point the `.atlas` page line at the `.webp`, and don't commit the PNG. spine-player loads pages as plain images, so the format is transparent to it.
- **`<SpinePortrait>` wants a `fallback`** — pass the static bust `<img>` so the cell shows it during the skel/atlas fetch and degrades to it if WebGL/loading fails (it's an underlay, auto-hidden once the live skeleton paints). Players also lazy-init via IntersectionObserver, and the `viewport` prop is compared by value (inline literals won't churn the player). The cover strip no longer wires this by hand — use `<CoverPortrait name filter>` which owns the Spine→tall→bust chain for all themes.
- **A new cover-strip resonator with no `TEAM_FRAME` entry uses `DEFAULT_FRAME`** (centered, height 245%). That's a safe neutral but may need a live-dial — measure the sprite's alpha bounds (head-top + head→chest band) like the other entries in `src/lib/portraits.ts` once you can see it framed in the Teams cell.
- **Benchmark `rank` must equal array position** (1-based). The CLI's `renumberBenchmarks()` enforces it after every add/move/sort/remove; don't hand-edit a `rank` out of sync — the Emberline render and the bar-width math assume the order.
